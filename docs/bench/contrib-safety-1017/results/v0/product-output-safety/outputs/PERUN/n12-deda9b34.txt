### Product Output Safety Review: PodCastly Transcript Summariser

**1. Harm Inventory (MAP)**
Before launch, explicitly record these risks for your specific feature:
*   **Hallucination as Fact:** The summary attributes a view, quote, or stance to the host that was never expressed in the episode.
*   **Tone Distortion:** The blurb captures the facts but misrepresents the host's sentiment (e.g., framing a sarcastic remark as sincere, or a tentative hypothesis as a definitive claim).
*   **Over-reliance:** Listeners treat the blurb as a verified abstract rather than a machine-generated approximation, skipping the actual episode based on potentially flawed premises.
*   **Missing AI Disclosure:** Users are unaware the blurb is automated, assuming a human editor curated the host's voice.

**2. Measurement Plan (MEASURE)**
Do not assert accuracy; run these specific internal tests immediately. Create one test row per harm:

*   **Probe Set A (Adversarial Tone):** Feed the model episodes containing heavy sarcasm, irony, or hedging ("I might be wrong, but...").
    *   *Positive Control:* Input where the host clearly jokes; expect the output to flag humor or avoid literal interpretation.
    *   *Negative Control:* Input with straightforward facts; expect literal summary.
    *   *Metric:* % of outputs that incorrectly literalize sarcasm or remove necessary hedging.
    *   *Stop Condition:* If >0% of high-stakes tone errors occur in the sample, block launch.
*   **Probe Set B (Attribution Integrity):** Feed episodes with multiple speakers or guest interviews.
    *   *Probe:* Instances where a guest holds a controversial view distinct from the host.
    *   *Metric:* Frequency of the summary attributing the guest's view to the host.
    *   *Stop Condition:* Any instance of misattribution triggers a mandatory human review gate.
*   **Probe Set C (Fabrication Check):** Include episodes with niche, verifiable claims.
    *   *Metric:* Count of specific facts in the blurb not present in the source transcript.
    *   *Result Reporting:* Report this as "UNVERIFIED" until the test runs. Do not invent a "99% accurate" figure.

**3. Risk Management (MANAGE)**
*   **Human-in-the-Loop Gate:** Since publishing a blurb under a host's name is an irreversible action that impacts their reputation, **no summary should publish automatically.** Implement a mandatory human approval step for every blurb before it goes live. This is non-negotiable for high-stakes reputation management.
*   **Uncertainty & Disclosure:**
    *   Do not display raw confidence scores (e.g., "87% confident") to users; this implies false precision.
    *   Add a visible disclosure: "This blurb was generated by AI and reviewed by [Team Name/Host]."
    *   Provide an easy mechanism for hosts to flag or correct a blurb post-publication.
*   **Transparency Artifact:** Draft a one-page "Model Card" for internal use and host partners. It must list: intended use (episode previews), known limitations (struggles with sarcasm/irony), and the results of the tests above. If a metric is unmeasured, label it `UNVERIFIED`.

**4. Governance (GOVERN)**
*   Name a specific owner (e.g., "Head of Product") responsible for reviewing any host complaints about misrepresentation.
*   Re-run the tone and attribution tests if you change the underlying model or prompt logic.

**Note:** I cannot certify this system as "safe" or "unbiased"; only your test results can inform that decision. If legal questions arise regarding liability for misrepresentation, route those immediately to counsel.
