**Do not switch this system to fully automated mode.**

Freezing a customer's bank card is a high-stakes, irreversible action with immediate real-world consequences (stranding users without funds for food or travel). Deploying an autonomous agent to execute this without a human-in-the-loop gate violates the fundamental safety floor for product outputs. No latency constraint justifies removing the human review step for actions this costly.

**Required Immediate Controls:**

1.  **Human-in-the-Loop Gate:** The system must not freeze cards autonomously. Instead, high-confidence alerts should trigger an immediate temporary hold (e.g., 15 minutes) while routing the case to a human agent for verification. Only the human agent executes the permanent freeze. If human staffing cannot meet the 200ms decision window, the system must default to allowing the transaction and flagging it for post-hoc review, rather than risking a false positive block.
2.  **Defined Uncertainty Tiers:** Do not use raw probability scores (e.g., "87% fraud risk") to drive decisions or display status to users. Replace these with defined coarse tiers:
    *   **Confirmed:** Multiple strong signals + human verification. Action: Freeze.
    *   **Corroborated:** Strong signals + pattern match. Action: Temporary hold + urgent human review.
    *   **Unverified:** Single weak signal. Action: Allow transaction, log for analysis.
3.  **Harm Inventory & Measurement Plan:** Before any deployment, you must document the following for each harm category:
    *   **Bias:** Who is disproportionately affected? (e.g., travelers, specific demographics). *Test:* Run adversarial prompts and edge-case inputs segmented by user group.
    *   **False Positives:** What is the worst-case scenario? (Customer stranded). *Test:* Inject known-good transaction patterns that resemble fraud; measure the rate of incorrect holds.
    *   **Over-reliance:** Does the interface encourage agents to blindly trust the score? *Test:* Observe agent override rates when the system is wrong.
    *   **Metric Reporting:** Do not invent a "false positive rate." If you have not run the specific evals above, the rate is **UNVERIFIED**. Publish the evaluation plan and the residual risk, not a fabricated clearance number.
