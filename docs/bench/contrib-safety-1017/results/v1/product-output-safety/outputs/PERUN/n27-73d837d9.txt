**Do not switch this system to fully automated mode yet.** Freezing a customer's bank card is a high-stakes, irreversible action that causes immediate harm (stranding users without funds for food or travel). Automating this without a human-in-the-loop gate violates the fundamental safety floor for product outputs.

**Immediate Action Plan: The Human Gate & Tiered Response**

1.  **Implement a Human-in-the-Loop (HITL) Gate:**
    *   **High-Confidence/High-Impact Alerts:** Any detection triggering a full card freeze must route to a human agent for verification before execution. The 200ms latency constraint applies to the *detection* score, not the *action*. The system should flag the transaction instantly, place a temporary "pending review" hold (if legally/technically feasible without a full freeze), and alert an agent. The actual freeze happens only after human confirmation.
    *   **Alternative:** If a temporary hold is impossible, the system must allow the transaction to proceed if it cannot be verified by a human within a strict time window (e.g., 30 seconds), accepting the fraud risk to prevent the certainty of harming a legitimate user. False negatives (fraud gets through) are preferable to false positives (legitimate user stranded) in this specific high-stakes context.

2.  **Replace Binary Freezes with Tiered Responses:**
    *   **Low/Medium Confidence:** Do not freeze. Instead, trigger a low-friction user verification (e.g., an instant push notification asking "Did you make this purchase?" with Yes/No buttons). This respects the latency constraint and minimizes friction.
    *   **High Confidence:** Trigger the HITL gate described above. Never auto-freeze based solely on algorithmic confidence.

3.  **Define Confidence as Tiers, Not Percentages:**
    *   Do not display or rely on raw model scores (e.g., "87% likely fraud") for decision thresholds. These imply a precision the model likely lacks.
    *   Define clear, coarse tiers: **"Corroborated"** (multiple strong signals + human review), **"Single-Source"** (one strong signal), **"Unverified"** (weak signals). Only "Corroborated" cases should even consider a freeze, and only with human approval.

What is the worst-case scenario (e.g., medical emergency, stranded abroad)? This must be written down before deployment.

Your false positive rate for critical demographics is currently **UNVERIFIED**. You need an evaluation plan with specific test rows:
