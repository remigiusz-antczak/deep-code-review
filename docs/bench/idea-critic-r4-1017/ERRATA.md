# Errata (recorded 2026-10-17, after review; PREREGISTERED-CHOICE.md is left unedited because its hash is frozen in SHA256-choice.txt)

1. The tune table in PREREGISTERED-CHOICE.md (v0 0.55, cA 0.65, cB 0.50, cC 0.50) and the committed `results4-idea-critic-PERUN_*-tune.json` files (v0 0.55 [0.35, 0.75], cA 0.60 [0.50, 0.75], cB 0.55 [0.40, 0.70], cC 0.50 [0.30, 0.70]) disagree, and the two cannot be reconciled from this tree; see item 2. Both versions rank cA first, but the committed files rank it first by one tie-to-win conversion (0.5 points), so the selection of cA is uncertain.
2. The committed judge records for tune scenarios 01, 02 and 03 (`judge4/idea-critic/PERUN_*/0[1-3].json`, 12 records, all four arms) have every order null. `ledger.jsonl` shows that each of their judge calls succeeded once (usage present, no error) and that the same tags were also called by a second, overlapping judge pass whose requests all failed (URLError/HTTPError, four attempts each). The driver checks for an existing record only when a judge pass starts, so the later failing pass most likely overwrote the completed records with null orders. The original verdicts are not preserved. The table in PREREGISTERED-CHOICE.md may reflect them, but this cannot be confirmed, and the claim in that file that every tune record was complete cannot be confirmed either. The held-out records are all complete (6 of 6 calls each), so the held-out result is unaffected.
3. The cA h10 held-out record was re-judged because one order was missing after the driver's retry. The ledger shows no request error on its first-pass calls and a second GLM-5.2 call, which fits judge output that could not be parsed twice rather than a failed request. The deleted original is not preserved. The criterion applied was "a held-out record with a missing order is re-judged once"; v0 h19 also has a retried GLM-5.2 call, but its retry parsed, so it had no missing order and was not re-run. Effect on cA is at most 0.0125, and cA is reverted.
